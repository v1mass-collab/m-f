Task 1: Pushing Multi-Folder Project to a Private Repository
Create a Private repository on [https://github.com](https://github.com) (New repository -> enter name -> check Private -> Create repository).

Initialize Git in your project folder:
mkdir myproject3334
cd myproject3334
git init

Add the remote repository:
Bash
git remote add origin https://github.com/yourusername/your-private-repo.git
git remote -v

Stage and commit files:
Bash
git add .
git commit -m "Initial commit"

Push to the remote repository:
Bash
git push -u origin master

git push -u origin main
```[cite: 11, 12]

```bash

```bash

### 4. Branching, Merging, Rebasing, and Remotes
```bash

git branch branch-name
git branch -d branch-name
git branch -D branch-name

git checkout -b new-branch
git remote prune origin

git checkout main

### 5. Undoing Changes and Viewing History
```bash

git log

git diff
git show commit-hash

git commit --amend -m "Corrected commit message"
```[cite: 20, 21, 22]

git merge another-branch

git commit
touch .gitignore
git blame login.js
git stash
git switch another-branch
git switch main
git stash apply
git branch --merged
git branch -d branch1 branch2 branch3
```[cite: 23, 24, 25, 26, 27]

Go to GitHub, click New organization, and select Create a free organization.

Enter organization details (name, associated email, verification) and click Next.

Add members to the group, have collaborators accept invitations, and click Complete setup.

Configure base permissions under Settings > Member privileges > Base permissions (e.g., Write for repository/project base permissions as shown).

Create the remote repository inside the organization (e.g., Teams-project-1/SE_remote_109876) and manage collaborator roles under Settings > Collaborators and teams.

#### Fork & Pull Request Workflow
1. Open the target public repository on GitHub and click **Fork** at top-right.
2. Clone your forked copy and push changes:
```bash
git clone https://github.com/your-username/awesome-project.git
git add .
git commit -m "Update file"
git push origin main
```[cite: 45, 46]
3. Open a **Pull request** back to the original repository, review changes (**Files changed > Review changes > Comment / Approve / Request changes > Submit review**), and click **Merge pull request**[cite: 46, 47].
4. Sync local branches:
```bash
git checkout main
git pull origin main
git checkout feature/your-new-feature
git merge main
```[cite: 48]

#### 2. Resolving Merge Conflicts
```bash
git checkout -b feature-person2
echo "Hello from Person 2" >> README.md

When a conflict occurs:

### Scenario Based Questions on Working with Remote Repository

**Q1.** You've cloned a repository and made some changes to a local branch. Now you want to push these changes to the remote repository, but you're getting an error saying "rejected - non-fast-forward." How would you resolve this?
**A1.**
```bash
git pull --rebase origin main
git push origin main
```[cite: 54]

**Q2.** You've been working on a feature branch, and now you need to push it to the remote repository. However, the remote repository already has a main branch. How do you push your feature branch without affecting the main branch?
**A2.**
```bash
git push -u origin feature
```[cite: 54]

**Q3.** You cloned a remote repository, but after a while, the repository's structure changed and new branches were added. How would you keep your local repository updated with the latest changes from the remote repository?
**A3.**
```bash
git fetch --all
git branch -r
```[cite: 54]

**Q4.** A colleague has pushed some changes to the main branch, but you have local changes in the same branch. You want to pull their changes, but you want to avoid merge conflicts. What steps would you take?
**A4.**
```bash
git stash
git pull --rebase origin main
git stash pop
```[cite: 54]

**Q5.** You accidentally pushed a sensitive file (e.g., API keys) to the remote repository. How would you fix this situation?
**A5.**
```bash
git filter-repo --path api-key.txt --invert-paths
git push --force origin main
```[cite: 54]

**Q6.** You're working on a feature branch, and your manager requests that you integrate the latest changes from main into your feature branch. What steps would you take?
**A6.**
```bash
git switch feature-branch
git fetch origin
git merge origin/main
```[cite: 54, 55]

**Q7.** You cloned a remote repository, but later you find that you need to push your changes to a different remote repository. How do you configure your local repository to push to this new remote?
**A7.**
```bash
git remote set-url origin https://github.com/hello-tej.git
```[cite: 55]

**Q8.** After running `git pull`, you notice that your local branch is behind the remote branch. How would you proceed to bring your local branch up to date without losing your local changes?
**A8.**
```bash
git pull --rebase origin main
```[cite: 55]

**Q9.** You're working on a project with multiple collaborators, and you notice that your local changes conflict with changes that have been pushed by others. How would you resolve the conflicts?
**A9.**
```bash
git pull origin main
git add .
git commit
git push origin main
```[cite: 55]

**Q10.** You've pushed a feature branch to a remote repository, but now you need to delete the branch from the remote. How would you do that?
**A10.**
```bash
git push origin --delete feature-branch
```[cite: 55, 56]

**Q11.** (Four-developer scenario: `feature/ui-update`, bug fix pushed to `main`, push fails due to upstream changes, teammate sends `fix.patch`.) What command will you use to bring your local main branch up to date with the remote repository before merging it into your feature branch?
**A11.**
```bash
git switch main
git pull origin main
```[cite: 56]

**Q12.** How will you update your `feature/ui-update` branch to reflect the latest changes from main?
**A12.**
```bash
git switch feature/ui-update
git merge main
```[cite: 56, 57]

**Q13.** Which command should you use to attempt pushing your local feature branch again, and what should you do if it fails due to conflicts?
**A13.**
```bash
git pull --rebase origin feature/ui-update
git push origin feature/ui-update
```[cite: 57]

**Q14.** How do you apply a patch file provided by your teammate and include it in your commit history?
**A14.**
```bash
git apply fix.patch
git add .
git commit -m "Applied CSS patch"
```[cite: 57]

**Q15.** After successful testing, describe the steps (with commands) to merge your feature branch into main and push it to GitHub.
**A15.**
```bash
git switch main
git merge feature/ui-update
git push origin main
```[cite: 57]
